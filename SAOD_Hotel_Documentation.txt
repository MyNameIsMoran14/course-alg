ЧАСТЬ 1. ТЕХНИЧЕСКАЯ ДОКУМЕНТАЦИЯ К ПРОЕКТУ (ПОЯСНИТЕЛЬНАЯ ЗАПИСКА)
--------------------------------------------------------------------------------

1.1. ОПИСАНИЕ СТРУКТУР ДАННЫХ И СПЕЦИФИКАЦИЯ ФОРМАТОВ ПFields (п. 2.2.3)
В соответствии с выданным заданием, в разработанной информационной системе 
функционируют три взаимосвязанные структуры данных, оптимизированные под конкретные 
операции поиска, вставки и удаления. Длина строковых полей (кроме фиксированных 
форматов первичных ключей) определена самостоятельно исходя из соображений оптимального 
использования оперативной памяти и дискового пространства.

1.1.1. Данные о гостиничных номерах (АВЛ-Дерево)
  - Структура хранения: Сбалансированное по высоте двоичное (АВЛ) дерево поиска. 
    Обеспечивает гарантированную скорость выполнения операций поиска, вставки и 
    удаления за время O(log n) за счет автоматической балансировки.
  - Первичный ключ: № гостиничного номера.
  - Спецификация полей (согласно п. 2.2.3.4 методических указаний):
    * id (№ гостиничного номера): Строка строгого формата "ANNN", где:
        A - символьный код типа номера ("Л", "П", "О", "М").
        NNN - трехзначное числовое обозначение номера (от 000 до 999).
        Пример правильного ключа: Л101, П205, М310.
    * type (Тип номера): Текстовое поле, дублирующее символьный код из ключа для 
      явной человекочитаемой типизации (Люкс, Полулюкс, Одноместный, Многоместный).
    * seats (Количество мест): Целое положительное число (количество спальных мест).
    * rooms_cnt (Количество комнат): Целое положительное число.
    * toilet (Наличие санузла): Логическое/булево значение (1 — есть, 0 — нет).
    * equip (Оборудование номера): Текстовая строка произвольной длины, содержащая 
      перечень материальных ценностей через запятую (например: "Телевизор, холодильник, сейф").

1.1.2. Данные о постояльцах (Хеш-таблица)
  - Структура хранения: Хеш-таблица с открытым списочным разрешением коллизий 
    (метод цепочек / односвязные списки). Обеспечивает среднее время поиска O(1).
  - Первичный ключ: № паспорта постояльца.
  - Спецификация полей (согласно п. 2.2.3.2 методических указаний):
    * passport (№ паспорта): Строка строгого фиксированного формата "NNNN-NNNNNN", 
      где N — цифры (серия из 4 цифр, дефис, номер из 6 цифр).
      Пример правильного ключа: 4515-123456.
    * fio (ФИО постояльца): Строка произвольной длины (до 150 символов).
    * birth (Год рождения): Целое четырехзначное число (например: 1995).
    * address (Адрес постоянного места жительства): Строка произвольной длины.
    * goal (Цель прибытия): Строка произвольной длины (например: "Деловая поездка", "Туризм").
    * checkout_date (Статус / Дата выселения): Строковая переменная. Принимает 
      значение "Проживает", если постоялец находится в гостинице в данный момент, 
      либо содержит строковую метку даты и времени выселения после выполнения операции.

1.1.3. Журнал вселения-выселения (Слоеный список / Skip List)
  - Структура хранения: Рандомизированный многоуровневый слоеный список (Skip List). 
    Обеспечивает логарифмическую скорость поиска и вставки O(log n).
  - Ключ сортировки: № гостиничного номера (строка формата "ANNN").
  - Спецификация полей (согласно п. 2.2.3.6 методических указаний):
    * room_id: Номер комнаты (внешний ключ, связывающий журнал с АВЛ-деревом комнат).
    * guest_pass: Номер паспорта постояльца (внешний ключ, связывающий журнал с Хеш-таблицей).

ЧАСТЬ 2. ПОДРОБНОЕ ТЕОРЕТИЧЕСКОЕ И ПРАКТИЧЕСКОЕ ОПИСАНИЕ АЛГОРИТМОВ
--------------------------------------------------------------------------------

2.1. АВЛ-ДЕРЕВО (СБАЛАНСИРОВАННОЕ ДЕРЕВО ПОИСКА)
АВЛ-дерево — это двоичное дерево поиска, обладающее свойством самобалансировки: для 
каждого узла дерева высоты его левого и правого поддеревьев различаются не более чем на 1.

Как работает алгоритм в программе:
1. Поиск позиции и вставка: При добавлении нового номера узел спускается от корня вниз. 
   Если вставляемый ключ меньше ключа текущего узла, алгоритм уходит в левое поддерево; 
   если больше — в правое. Если ключ полностью совпадает, происходит перезапись полей данных.
2. Проверка дисбаланса: При возвращении из рекурсии вверх по дереву для каждого пройденного 
   родительского узла пересчитывается его высота: height = 1 + max(height(left), height(right)). 
   Затем вычисляется фактор баланса (Balance Factor) как разность высот левого и правого потомков.
3. Балансировка поворотами: Если фактор баланса выходит за рамки интервала [-1; 1] (становится 
   равным 2 или -2), структура дерева выпрямляется с помощью вращения узлов:
   - Малый правый поворот (rotate_right): Выполняется, когда левое поддерево стало длиннее правого. 
     Левый потомок становится новым локальным корнем поддерева, а старый родитель уходит вправо.
   - Малый левый поворот (rotate_left): Выполняется, когда правое поддерево длиннее левого. 
     Правый потомок занимает место родителя, а родитель смещается влево.
   - Большие повороты (комбинация левого и правого): Выполняются, если дисбаланс вызван «внутренним» 
     потомком (возник изгиб структуры зигзагом). Сначала выполняется малый поворот для поддерева, 
     а затем противоположный малый поворот для его родителя.

2.2. СИСТЕМАТИЧЕСКИЙ ПРЯМОЙ ОБХОД ДЕРЕВА (PRE-ORDER TRAVERSAL)
Для реализации поиска по фрагментам и вывода общего списка комнат на экран используется 
систематический обход всех узлов дерева в глубину.

Как работает алгоритм в программе:
Алгоритм последовательно обрабатывает узлы по строгому рекурсивному правилу "Корень-Лево-Право":
1. Проверяется, не является ли текущий узел пустым (None).
2. Обрабатывается корень: текущий узел AVLNode добавляется в результирующий плоский список.
3. Рекурсивно вызывается метод обхода для всего левого поддерева текущего узла.
4. Рекурсивно вызывается метод обхода для всего правого поддерева текущего узла.
Такой подход гарантирует полное сканирование структуры без пропусков за линейное время O(n).

2.3. АЛГОРИТМ БОУЕРА-МУРА (ПОИСК ПОДСТРОКИ В СТРОКЕ)
Алгоритм Боуера-Мура — это эталонный высокоэффективный алгоритм, предназначенный для 
поиска подстроки (шаблона) в большой строке текста. Его ключевое преимущество — сканирование 
текста со скоростью, превышающей стандартный посимвольный перебор, за счет пропуска заведомо 
неподходящих позиций.

Как работает алгоритм в программе:
1. Эвристика «плохого символа» (Предобработка): До начала сравнения алгоритм строит таблицу 
   смещений (словарь) для всех символов искомого шаблона. Для каждого символа вычисляется 
   расстояние от его последней позиции в слове до конца шаблона. Символы, отсутствующие 
   в шаблоне, получают значение смещения, равное полной длине шаблона.
2. Процесс сравнения: Шаблон прикладывается к началу текста. Сравнение символов выполняется 
   справа налево (от конца шаблона к началу).
3. Прыжки по тексту: Если обнаружен несовпадающий символ, алгоритм берет его значение из 
   заранее рассчитанной таблицы смещений и сдвигает (перемещает) весь шаблон вправо сразу 
   на несколько символов, минуя ненужные проверки.

2.4. ХЕШ-ТАБЛИЦА С МЕТОДОМ ЦЕПОЧЕК
Хеш-таблица — это структура данных, реализующая ассоциативный массив, которая позволяет 
производить операции вставки, удаления и поиска элементов по ключу за константное время O(1).

Как работает алгоритм в программе:
1. Вычисление хеша: Номер паспорта (строка) передается в хеш-функцию. Функция итерируется 
   по каждому символу строки, суммирует их числовые коды ASCII, а затем вычисляет остаток 
   от деления полученной суммы на фиксированный размер внутренней таблицы (в коде size = 10):
   Index = (Сумма ASCII кодов символов ключа) % Size
   Полученный индекс указывает на конкретную ячейку массива (бакет), где должен храниться объект.
2. Разрешение коллизий: Так как разные номера паспортов при делении по модулю могут давать 
   одинаковый индекс (ситуация коллизии), каждая ячейка таблицы хранит ссылку на начало 
   односвязного списка узлов HashNode. Метод вставки вычисляет индекс, переходит к цепочке, 
   проверяет её элементы: если элемент с таким паспортом уже существует, обновляет его данные; 
   если цепочка закончилась — добавляет новый узел в конец списка цепочки.

2.5. СЛОЕНЫЙ СПИСОК (SKIP LIST)
Слоеный список — это вероятностная динамическая структура данных, построенная на основе 
нескольких уровней параллельных односвязных списков. Нижний уровень (уровень 0) содержит 
абсолютно все элементы в отсортированном порядке, а верхние уровни служат "экспресс-каналами" 
для быстрого перемещения, пропуская большие группы элементов.

Как работает алгоритм в программе:
1. Поиск элемента: Алгоритм начинает поиск с самого верхнего существующего уровня от заголовочного 
   элемента (header). Он движется вправо по указателям forward, пока ключ следующего узла меньше 
   искомого. Как только обнаруживается, что следующий узел больше искомого или равен None, алгоритм 
   опускается на один уровень ниже и продолжает движение вправо на новом уровне.
2. Вероятностная вставка: При добавлении новой записи генерируется случайное число (эмуляция 
   подбрасывания монетки). На основе генератора случайных чисел random.random() вычисляется 
   высота («количество этажей») для нового узла. С вероятностью 50% узел поднимается на уровень выше.
3. Перестройка ссылок: На основе массива update (в котором сохранены ссылки на крайние левые 
   элементы перед точкой вставки на каждом уровне) новые узлы встраиваются в цепочки указателей.

Ниже приведены готовые практические сценарии для тестирования и наглядной демонстрации

ТЕСТ-КЕЙС №1: ДЕМОНСТРАЦИЯ КОЛЛИЗИЙ В ХЕШ-ТАБЛИЦЕ (МЕТОД ЦЕПОЧЕК)
Цель: Показать, что при совпадении хэш-кодов программа не перезаписывает данные постояльцев, 
а связывает их в цепочку, сохраняя доступ ко всем записям.

Шаги выполнения:
1. Перейдите во вкладку «Журнал» (или «Реестр»).
2. Добавьте первого постояльца с номером паспорта: 1111-000002
   ФИО: Иванов Иван Иванович, Год: 1990, Адрес: Москва, Цель: Бизнес, Номер: Л101.
   (Хеш-функция посчитает сумму ASCII символов и вернет определенный индекс ячейки).
3. Добавьте второго постояльца с номером паспорта: 1111-000020
   ФИО: Петров Петр Петрович, Год: 1993, Адрес: Тверь, Цель: Отпуск, Номер: П201.
   (Ключ состоит из тех же символов, цифры 2 и 0 просто поменялись местами. Хеш-функция вернет 
   абсолютно такой же индекс ячейки — возникнет явная коллизия).
4. Перейдите во вкладку «Реестр» и введите в поиск «1111».
Результат анализа: В терминале (благодаря debug-принту) вы увидите одинаковый индекс бакета, 
но в графическом интерфейсе приложения успешно отобразятся ОБОИ постояльца. Элементы корректно 
разместились в памяти внутри одной ячейки методом цепочек.

ТЕСТ-КЕЙС №2: БАЛАНСИРОВКА АВЛ-ДЕРЕВА (МАЛЫЙ ЛЕВЫЙ ПОВОРОТ)
Цель: Показать алгоритм автоматического удержания баланса высоты дерева при критическом 
одностороннем заполнении.

Шаги выполнения:
1. Перейдите во вкладку «Номера».
2. Последовательно добавьте три номера строго по возрастанию ключа:
   - Номер: Л100 (Становится корневым узлом дерева, высота = 1).
   - Номер: Л200 (Вставляется в правое поддерево от Л100. Дерево разбалансировано, фактор баланса Л100 = -1).
   - Номер: Л300 (Вставляется в правое поддерево от Л200. Фактор баланса корня Л100 становится равен -2).
Результат анализа: Алгоритм автоматически фиксирует нарушение баланса (разница высот левого и правого 
поддеревьев у корня Л100 стала равна -2) и выполняет малый левый поворот вокруг Л100. В результате 
новым локальным корнем дерева становится узел Л200, узел Л100 уходит в его левое поддерево, а Л300 
остается в правом. Дерево сохранило логарифмическую структуру, глубина уменьшилась с 3 до 2 уровней.

ТЕСТ-КЕЙС №3: РАБОТА ПОИСКОВОГО ДВИЖКА БОУЕРА-МУРА И ПРЯМОГО ОБХОДА
Цель: Проверить корректность связки алгоритма прямого обхода дерева и фильтрации текста Боуером-Муром.

Шаги выполнения:
1. Во вкладке «Номера» добавьте три тестовых записи:
   - Номер: О101, Оборудование: "Телевизор, фен, чайник"
   - Номер: П202, Оборудование: "Микроволновка, сейф, минибар"
   - Номер: Л303, Оборудование: "Кондиционер, Телевизор, джакузи"
2. В поле «Поиск по оборуд.» введите поисковый фрагмент: "телевиз" (без кавычек) и нажмите кнопку «Поиск».
Результат анализа: Программа запустит метод прямого обхода дерева (Pre-order), извлечет из каждого узла 
строку оборудования, переведет ее в нижний регистр и пропустит через функцию boyer_moore_search. 
На экране мгновенно отобразятся только два номера — О101 и Л303, так как в их оборудовании содержится 
искомый фрагмент подстроки. Номер П202 будет успешно отфильтрован.
